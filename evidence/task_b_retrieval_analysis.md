对应闸门：`acceptance/gates/g1_memory.py`（GOLDEN 8 对，宏平均查准/查全 ≥0.8）。
实现：`src/memory_ranker.py`（五层打分）+ `src/memory_store.py`（`score_retrieval` 委托、`recall_relevant`、`format_memory_prompt`）。
评测口径（top-1 + 宏平均，退化情形约定）写在 `memory_ranker.score_retrieval` 的 docstring，此处不重复。

结果先行：**golden 8/8 全中（P=R=1.0），留出集 12/12 全中（P=R=1.0）**。留出集在实现前定稿，实现过程中未改动一字。

## 一、五层模型与各层分工

| 层 | 函数 | 信号 | 负责的样例形态 |
|---|---|---|---|
| L1 | `normalize` | NFKC + 小写 + 剥空白/中英文标点 | 全角半角混写（「7月12日」）不干扰后续层 |
| L2 | `bigram_similarity` | 字符 bigram 多重集余弦，唯一不依赖词典的信号 | 字面重叠高的对：颜色/生日/称呼/过敏 |
| L3 | `concept_bridge` | 8 类概念词典双侧命中桥接 | 零字面重叠的对：职业/爱好/城市/宠物 |
| L4 | `preference_bonus` | 偏好断言谓词加分（仅稳定属性提问） | 「喜欢/希望」类事实优先于纯行为陈述 |
| L5 | `transient_penalty` | 时态标记扣分（仅稳定属性提问） | 「最近在健身」不抢占「爱好」的召回位 |

L3 的计分规则有两条硬约束：**双侧命中才计分**（单边命中贡献为 0，否则查询里的「喜欢」擦到爱好类 member 时，每条含「用户」的事实都会收集噪声分）；贡献值用几何均值 `sqrt(qh·fh)/(sqrt(qh·fh)+1)` 归一（弱双边命中低于强双边命中）。两条规则在 golden pair 7/8 上各有直接收益（见下）。

## 三、争议判断如实记录

### 3.1 pair 8 的口径本身有争议

golden 把「用户最近在健身」排除在「用户的爱好」的正确答案之外。这个口径可以争辩：健身完全可以是爱好，「最近」只说明该爱好近期活跃，不说明它不稳定。我们选择**对齐 golden 口径**（L5 时态降权），理由：

1. 评测集是冻结件，口径解释权在主仓侧；工作台单方面按自己的语言学判断实现，闸门就会红。
2. 产品语境下这个口径有独立正当性：注入 `extra_system` 的只有一条（top-1），「用户周末喜欢徒步」是显式偏好断言（喜欢），「最近在健身」是短期状态陈述——两者竞争同一个召回位时，稳定断言优先是合理的默认。
3. 但必须承认：**若主仓未来把「最近+活动」也视为爱好证据，L5 的这套门控就需要重新校准**。这是口径依赖，不是算法缺陷。

### 3.2 L4/L5 的结构性张力（已消解，但记录推导）

「用户最近在健身」同时带爱好类 member（健身）和时态标记（最近）；「用户周末喜欢徒步」带偏好谓词（喜欢）。若 L3 对单边命中也计分（如线性归一 qh+fh 口径），pair 8 里两条候选的 L3 会打平（各自单边命中 1 次），分差退化成 `W_PREFERENCE·1 − W_TRANSIENT·0.5` 的刀刃权重约束（干扰项 L4+L5 双吃）。实测的几何均值归一把干扰项的弱双边命中（qh=1、fh=1）压到 0.500，低于正确项的强双边命中（qh=1、fh=2，喜欢+徒步）的 0.586，**L3 自身就贡献了正分差，L4/L5 只是加深它**——敏感性网格（第五节）里最恶劣组合方向仍是 1.000，佐证了这一点。

残留风险（诚实记录）：若未来出现「干扰项双边命中同一概念类 + 带偏好谓词 + 带时态标记」而正确项不带谓词的样例，结构约束 `W_TRANSIENT > W_PREFERENCE` 会重新变成必要条件。当前 golden 与留出集都没有这种形状，但这是词典方案的可推导边界，不是实测结论。

### 3.3 「刚」是单字时态标记

会误伤「刚才/金刚」类词。只在稳定属性提问下生效，影响面可控；换成双字词表会漏掉「刚换/刚养」这类真实表达。留出集 pair 10（「用户刚换了新手机」）验证了它按预期工作。

### 3.4 稳定属性门控的误触发面

「喜欢」是爱好类 member 而非 head，门控只认 head 词，所以「用户喜欢吃什么」不会触发 L4/L5——但「用户对花过敏」会（过敏是 head）。当前语义上无碍（过敏本就是稳定属性），但这个门控是「查询含概念名」的近似，不是真正的意图识别。

### 4.1 必须直说的脆弱点：留出集 pair 6 是平局靠原序赢的

「用户吃不了什么」对两条候选的得分**完全相同**（+0.0500，L2 同为 0.1667、L3 均为 0）：查询不含任何词典词（「吃不了」不是过敏类 member，「忌口」才是），L3 静默；两条候选与查询的 bigram 余弦恰好相等。top-1 命中完全依赖 `relevant` 项恰好排在 `stored` 首位 + `rank()` 的同分按原序约定。**若 stored 顺序对调，这条会 miss，留出集掉到 11/12 = 0.917**（仍 ≥0.8，但这是运气不是能力）。

不修的原因：把「吃不了/不能吃」加进过敏类 member 当然能让这条真正分开，但那是**看着留出集的失败样例补词典**，与「不许改留出集迁就实现」是同一种 Goodhart 的镜像（改实现迁就留出集）。正确做法是把这个缺口留给主仓侧的真实语料去驱动：词典扩充应该来自线上 badcase，而不是来自评测集逐条对答案。此处如实上报为已知词典覆盖缺口。

## 五、权重敏感性分析

基线权重 `W_BIGRAM=0.30, W_CONCEPT=0.55, W_PREFERENCE=0.10, W_TRANSIENT=0.35`。扰动方式：运行期改写模块常量后重跑两个评测集（分析脚本为一次性产物，不入库；复现方法见文末）。

| 配置 | golden P/R | 留出 P/R | ≥0.8？ |
|---|---|---|---|
| 基线 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_BIGRAM ×0.5 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_BIGRAM ×2 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_CONCEPT ×0.5 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_CONCEPT ×2 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_PREFERENCE ×0.5 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_PREFERENCE ×2 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_TRANSIENT ×0.5 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_TRANSIENT ×2 | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| W_CONCEPT ×0.5 且 W_TRANSIENT ×2（结构最恶劣方向，见 3.2） | 1.000 / 1.000 | 1.000 / 1.000 | OK |
| 全体 ×2（等价于不动，验证合成是纯线性） | 1.000 / 1.000 | 1.000 / 1.000 | OK |

**结论：11/11 扰动配置下两集均保持 1.000，没有任何配置跌破 0.8。** 结论不建立在刀刃平衡上——golden 最小 top1−top2 分差为 0.2676（pair 8），最大的单权重扰动只能挪动分差约 ±0.1 量级。真正的刀刃不在权重，而在词典覆盖（4.1 的平局样例）：那一条对任何权重扰动都无感，因为两层信号本来就是 0。

复现方法（仓库根目录）：

```bash
./.venv/bin/python - <<'PY'
from src import memory_ranker as mr
from acceptance.gates.g1_memory import GOLDEN
from tests.test_memory_retrieval import HOLDOUT_GOLDEN
for factor in (0.5, 1.0, 2.0):
    for name in ("W_BIGRAM", "W_CONCEPT", "W_PREFERENCE", "W_TRANSIENT"):
        base = {"W_BIGRAM": 0.30, "W_CONCEPT": 0.55, "W_PREFERENCE": 0.10, "W_TRANSIENT": 0.35}
        for k, v in base.items():
            setattr(mr, k, v)
        setattr(mr, name, base[name] * factor)
        print(name, factor, mr.score_retrieval(GOLDEN), mr.score_retrieval(HOLDOUT_GOLDEN))
PY
```

## 六、反过拟合三条硬约束的落实位置

1. **词典通用性**：`tests/test_memory_retrieval.py::ConceptBridgeTests::test_lexicon_generality_against_golden` 机器断言每语义类 ≥3 个 member 不在 golden 集任何位置（query/stored/relevant 合并语料）出现。当前实测 unseen 数（要求 ≥3）：颜色 12、城市 13、称呼 7、生日 4、宠物 7、过敏 8、职业 12、爱好 12。
2. **留出验证集**：12 对（要求 ≥10），实现前定稿；`ScoreRetrievalTests::test_holdout_set_reaches_threshold` 持续把关。
3. **权重敏感性**：本文第五节，含最恶劣组合方向与平局脆弱点的如实披露。
